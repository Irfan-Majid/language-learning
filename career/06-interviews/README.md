# Interviews in the AI Era

How hiring changed — and how to win.

---

## What Changed Since AI

| Before | Now |
|--------|-----|
| "Can you write FizzBuzz?" | "Can you build and ship with AI assistance?" |
| Syntax memorization | Problem solving + code review |
| Whiteboard only | Take-home + discussion |
| "Do you know React?" | "How do you test AI-generated code?" |
| LeetCode grind | LeetCode + system design + behavioral |

**Good news:** Interviews still need **humans**. AI doesn't do the interview for you (yet) in most companies.

---

## Interview Types & Prep

| Type | What they test | Prep |
|------|----------------|------|
| **HR screen** | Communication, salary, culture | STAR stories, salary research |
| **Technical phone** | Coding, fundamentals | LeetCode easy/medium, your stack |
| **Take-home** | Real-world skills | Clean code, README, tests, deploy |
| **System design** | Senior thinking | URL shortener, chat, rate limiter |
| **Behavioral** | Team fit, ownership | 5 prepared STAR stories |
| **AI-specific (new)** | LLM integration, limitations | `ai-era/` knowledge |

---

## STAR Story Template

Prepare 5 stories covering: conflict, failure, leadership, deadline pressure, learning something new.

```
Situation:  [Context in 2 sentences]
Task:       [Your responsibility]
Action:     [What YOU did — specific steps]
Result:     [Measurable outcome: %, time, money, users]
```

**Example:**
> **S:** Our API had 5s response times during peak. **T:** I owned performance fix. **A:** Profiled queries, added Redis cache, indexed 2 columns. **R:** Latency dropped to 200ms, support tickets down 40%.

## Common Technical Questions (2026)

### All Levels
- Explain async/await in your language
- HTTP methods and status codes
- SQL: JOIN types, indexing basics
- Git: merge vs rebase, conflict resolution
- How do you use AI in your workflow? (NEW — prepare honest answer)

### Mid-Level
- Design a REST API for [resource]
- How would you cache this endpoint?
- Write tests for this function
- Debug this production scenario

### Senior
- Design Twitter/Slack/URL shortener at scale
- Microservices vs monolith tradeoffs
- How do you mentor juniors?
- Incident response process

### AI-Era Questions (Increasingly Common)
- What is RAG and when would you use it?
- How do you prevent prompt injection?
- How do you test an LLM-powered feature?
- What are hallucinations and how do you mitigate?

## Take-Home Project Tips

| Do | Don't |
|----|-------|
| README with setup steps | Submit without instructions |
| Tests (even 3–5) | Zero tests |
| Clean folder structure | One giant file |
| Deploy demo if possible | "Works on my machine" only |
| Note tradeoffs in README | Over-engineer unnecessarily |
| Mention AI tools used honestly | Hide that you used AI |

**AI-era honesty wins:** "I used Cursor for boilerplate; I wrote core logic and all tests myself."

## Questions to Ask Them (Shows Seniority)

- How does the team use AI tools in development?
- What does on-call look like?
- How are priorities set between product and tech debt?
- What would success look like in my first 90 days?
- Why is this role open?

|----|-------|
