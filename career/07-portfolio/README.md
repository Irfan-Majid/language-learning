# Portfolio — Proof That Secures Your Future

**Hiring managers trust GitHub more than claims.** A strong portfolio is layoff insurance.

---

## Minimum Viable Portfolio (2 Projects)

You need **at least 2 projects** that prove you can ship.

### Project 1: Full-Stack App (Required)

| Requirement | Example |
|-------------|---------|
| Frontend | React or Vue |
| Backend API | Express, FastAPI, or Laravel |
| Database | PostgreSQL or MySQL |
| Auth | Login/register (even simple) |
| Tests | 5+ unit tests |
| Deployed | Vercel + Railway, or similar |
| README | Setup, features, screenshots |

**Idea examples:** Task manager, expense tracker, book library, team wiki

### Project 2: AI-Era Project (Required in 2026)

| Requirement | Example |
|-------------|---------|
| LLM integration | OpenAI, Anthropic, or local model |
| Clear use case | Summarize, search docs, classify, chat |
| Error handling | API failures, rate limits |
| README section | "AI limitations" — shows maturity |

**Idea examples:** Document Q&A (RAG), code reviewer, meeting summarizer

Learn: [../../ai-era/](../../ai-era/)

## Portfolio Checklist

| Item | Done |
|------|------|
| GitHub profile photo + bio | ☐ |
| Pin 2–3 best repos on profile | ☐ |
| Every pinned repo has README | ☐ |
| README has: demo link, screenshots, tech stack | ☐ |
| No secrets in code (.env in .gitignore) | ☐ |
| Consistent commit history (not one giant commit) | ☐ |
| License file (MIT is fine) | ☐ |

## README Template

```markdown
# Project Name

One sentence: what it does and for whom.

## Demo
- Live: https://...
- Screenshot: ![](./screenshot.png)

## Tech Stack
- Frontend: React + TypeScript
- Backend: FastAPI
- Database: PostgreSQL
- AI: OpenAI API for document summarization

## Features
- User authentication
- CRUD for [resource]
- AI-powered [feature]

## Setup
\`\`\`bash
git clone ...
cd project
cp .env.example .env
npm install && npm run dev
\`\`\`

## Tests
\`\`\`bash
npm test
\`\`\`

## What I Learned
- [Honest reflection — interviewers read this]

## AI Usage Disclosure
I used [Cursor/Copilot] for [boilerplate/tests].
Core architecture and [specific parts] are my own work.
```

## What Recruiters Scan (30 Seconds)

1. **Pinned repos** — are they real projects?
2. **Last commit date** — active in last 3 months?
3. **README quality** — can they run it?
4. **Code structure** — not one file chaos?
5. **Tests** — any at all?

## Projects to AVOID as Portfolio Centerpieces

| Project | Why weak |
|---------|----------|
| Todo app with zero twist | Everyone has one — add AI or real deploy |
| Tutorial copy unchanged | Interviewers recognize course code |
| Incomplete repos | Worse than no repo |
| 50 half-finished repos | Shows lack of focus |

**Fix:** 2 polished > 10 broken.
